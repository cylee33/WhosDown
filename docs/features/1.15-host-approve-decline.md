## Goal

The Host manages their Match from one dashboard and answers each Join request with Approve or Decline (with an optional message). The Player hears about it in the app.

## Data

| ID | Read / write | Path and fields |
|---|---|---|
| R2 | read (listener) | `matches/{matchId}`: `pendingCount`, `joinedCount`, `playerLimit` |
| R3 | read (listener) | `rsvps` where `status == "pending"`, oldest `requestedAt` first |
| R20 | read | Each requester's Reliability (1.10) |
| W7 approve | write (transaction) | `rsvps/{userId}`: `status: "approved"`, `respondedAt`; `joinedCount += 1`, `pendingCount −= 1`, `attendeePreview`; notification `approved` to the Player |
| W7 decline | write (transaction) | `rsvps/{userId}`: `status: "declined"`, `respondedAt`, `hostResponse`; `pendingCount −= 1`; notification `declined` to the Player |
| Notification | write | `users/{playerId}/notifications/{id}`: `type`, `title`, `body`, `matchId`, `fromUserId`, `isRead: false`, `createdAt` |

**Security rules this feature needs:**

- Only the Match's Host can move another Player's RSVP from `pending` to `approved` or `declined`, with the matching counter changes.
- Approve only if `joinedCount + 1 ≤ playerLimit`.
- Notification create rule (D38): `fromUserId == auth.uid`, and the sender is the Match's Host or holds an RSVP in it. Recipient: read, update `isRead` only, delete.

## Rules and edge cases

1. Requests are listed oldest first.
2. **Full:** Approve is disabled with the label "Match is full", and requests stay pending (D24).
3. Approve is one tap (no sheet). Decline opens the sheet; the message is optional.
4. Approved Player: their screen turns green live (1.14), and they get an `approved` notification: "You're in: Pickup Soccer".
5. Declined Player: red H35 with the Host's message, and a `declined` notification.
6. A request cancelled by the Player (1.16) while the Host is looking disappears from the list. Acting on it fails quietly.
7. The Join requests row shows "No requests" when empty; H21 shows an empty state.
8. Only the Host sees H20 and H21.
9. Request after the Match started: requests close at start (1.14 rule 17). Anything still pending stays pending and can't be approved after the start.
