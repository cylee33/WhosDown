## Goal

After a Match starts, its Host records which approved Players actually came. Those records are the only data behind every Player's **Reliability** (GLOSSARY).

|---|---|---|
| R2 | read (listener) | `matches/{matchId}`: `title`, `startTime`, `endTime`, `status`, `hostId`, `checkedInAt` |
| R3 | read | `matches/{matchId}/rsvps` where `status == "approved"`: `displayName`, `skillLevel`, `isHost`, `attended` |

| **R20** (new) | read (count queries) | Reliability for one Player: count of `rsvps` collection group where `userId == X`, `checkedIn == true`, `attended == true`, divided by the count where `userId == X`, `checkedIn == true`. Needs a composite index in `firebase/firestore.indexes.json`. Built in 1.10; this feature makes the numbers real |

Add W20 and R20 to architecture §2 when built.

**Security rules this feature needs:**

- Only the Match's current Host (`hostId == auth.uid`) can set `checkedIn` and `attended` on that Match's RSVPs, and `checkedInAt` on the Match.
- Only while `startTime <= request.time <= endTime + 48h`, and only if the Match isn't cancelled.
- `attended` must be a bool; `checkedIn` can only be `true`.
- A Player can never change `checkedIn` or `attended` on their own RSVP.

## Rules and edge cases

1. **Window:** check-in is open from the Match's start time until 48 hours after its end time (D31). Outside the window, there is no entry row and the screen is read-only.
2. **Who is listed:** only RSVPs with status `approved` at the moment of check-in. Players who left, were declined, are pending, or are still waitlisted aren't listed and aren't counted.
3. **Default:** every Player starts as attended; the Host turns off no-shows (D31).
4. **The Host** is always attended, with no switch. This means the *current* Host: after a Host transfer (1.28), the new Host checks in and the former Host is listed as a Player.
5. **Submit** writes everything in one batch. A Match with only the Host can still be submitted.
6. **Redo:** the Host can change answers and submit again until the window closes. The screen opens with the saved answers.
7. **Cancelled Matches** can't be checked in.
8. **No check-in, no effect:** if the Host never submits, the Match doesn't change anyone's Reliability (D31).
9. **Reliability display** (used by 1.10, 1.15, 1.22, 1.28): a whole percent, e.g. "94% reliable". With zero checked-in Matches it reads "New player".
10. Players are **not notified** of their check-in result in V1.
