## Goal

Anyone can see who is going to a Match, each Player's level for this sport, and how reliably they show up.

## Screens

| Screen | What this feature owns on it |
|---|---|
| H11 Who's going | Subtitle "Pickup Soccer · Today 7:00 PM"; "12 / 14 joined"; Host first ("Host · 96% reliable"), then each approved Player (initials, name, "94% reliable · All Levels"); footer "Reliability reflects attendance, not playing skill." |

Leave out the V2 parts: friends chip and "friend" labels (2.1), "Invite a friend" (2.15).

## Data

| ID | Read / write | Path and fields |
|---|---|---|
| R2 | read | `matches/{matchId}`: `title`, `startTime`, `joinedCount`, `playerLimit`, `hostId` |
| R3 | read (listener) | `matches/{matchId}/rsvps` where `status == "approved"`: `userId`, `displayName`, `skillLevel`, `isHost` |
| **R20** (new) | read (count queries) | Per Player: count of collection group `rsvps` with `userId == X`, `checkedIn == true`, `attended == true` ÷ count with `userId == X`, `checkedIn == true` |

**Index:** collection group `rsvps` (`userId`, `checkedIn`, `attended`).

## Rules and edge cases

1. Host row first, then Players in the order they joined.
2. Reliability is a whole percent ("94% reliable"); with no checked-in Matches it reads "New player" (D31, 1.27 rule 9).
3. Level shown is the RSVP's `skillLevel` (the Player's level for this sport when they joined).
4. Only approved Players are listed. Pending and waitlisted Players aren't shown here (the Host sees requests in 1.15).
5. Tapping a row opens that Player's profile (H10, 1.22).
6. Reliability values are cached for the app session to avoid repeat count queries.
7. Visible to everyone, including Guests (D27).
