## Goal

A Player can report another Player or a Match for safety problems in a few taps.

## Screens

| Screen | What this feature owns on it |
|---|---|
| H33 Safety | "How WhosDown handles safety" card; "REPORT JAMIE" (or "REPORT THIS MATCH"); reasons: Harassment or unsafe behavior, No-show / repeated unreliability, Misleading Match information, Other; "Add details (optional)"; "Submit report" (red); "Emergency? Contact local emergency services." |
| Confirmation (no frame) | After submitting: "Thanks. We'll review your report." and back |

Leave out "Block user instead" (V2).

## Data

| ID | Read / write | Path and fields |
|---|---|---|
| W15 | write | New `reports/{id}`: `reporterId`, `reportedUserId` (or null), `matchId` (or null), `reason`, `details`, `status: "open"`, `createdAt` |

**Security rules this feature needs:** create only, with `reporterId == auth.uid`, a valid `reason`, `details` ≤ 1000 characters, `status == "open"`, and at least one of `reportedUserId` / `matchId`; can't report yourself; no client reads, updates, or deletes; Guests can't write.

## Rules and edge cases

1. Entry: "Safety & reporting" on H10 (reports that Player, plus the Match if opened from one), and "Report Match" in H09's ••• menu.
2. A reason is required; details are optional.
3. Submit is disabled while sending; on success, show the confirmation and go back.
4. A Player can't report themselves (no entry on their own profile).
5. Reporting doesn't change anything visible to the reported Player.
6. Guests get the Guest gate (1.3).
