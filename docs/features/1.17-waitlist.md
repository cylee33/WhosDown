## Goal

When a Match is Full, Players can line up. On an Open Match, the first in line gets in automatically when a spot opens. On an Approval-required Match, the Host lets people in.

## Data

| ID | Read / write | Path and fields |
|---|---|---|
| Join waitlist | write (transaction) | `rsvps/{me}`: `status: "waitlisted"`, `requestedAt`, plus the usual RSVP fields; `matches/{id}.waitlistIds` gets `me` appended; `waitlistCount += 1` |
| Leave waitlist (1.16) | write (transaction) | `rsvps/{me}.status = "left"`; `me` removed from `waitlistIds`; `waitlistCount −= 1` |
| Auto-promote (Open) | write (inside the leave or limit-change transaction) | First ID in `waitlistIds` (or first N for N new spots): RSVP `status: "approved"`, `respondedAt`; removed from `waitlistIds`; `waitlistCount −= 1`, `joinedCount += 1`; `approved` notification "You're in from the waitlist: Pickup Soccer" |
| Host approves from waitlist (Approval required) | write (transaction) | That Player's RSVP `status: "approved"`; removed from `waitlistIds`; `waitlistCount −= 1`, `joinedCount += 1`; `approved` notification |
| `spotOpened` | write (inside the leave transaction) | On an Approval-required Match, if `waitlistIds` or `pendingCount` isn't empty: notification to the Host "A spot opened in Pickup Soccer · 3 waiting" |
| R3 | read | `rsvps` where `status == "waitlisted"` for names; order from `waitlistIds` |

**Security rules this feature needs:**

- Join waitlist only when the Match is Full, `waitlistEnabled`, scheduled, and not started; `waitlistIds` must change only by appending your own uid.
- **Auto-promote** (Open Match): a Player may set **another** Player's RSVP from `waitlisted` to `approved` only when their own RSVP goes from `approved` to `left` in the same write, the promoted uid is `resource.data.waitlistIds[0]`, and `waitlistIds` loses exactly that first entry. The Host may do the same when raising `playerLimit` (1.18).
- **Host approve** (Approval required): only the Host, only while `joinedCount < playerLimit`, and the uid must be in `waitlistIds`.

## Rules and edge cases

1. Order is the order of `waitlistIds`; position = index + 1.
2. **Open Match:** each freed spot goes to the first in line, automatically, in the same transaction that freed it. Two freed spots go to the first two.
3. **Approval-required Match:** nothing happens automatically. The Host gets `spotOpened` and approves anyone from Join requests or Waitlist, in any order, while a spot is free (Q2, round 9).
4. Joining the waitlist needs no approval and has no note.
5. Full with no waitlist (`waitlistEnabled == false`): the button says "Full" (disabled), plus "Find similar Matches" (D24).
6. Pending Join requests can't be approved while the Match is Full (D24, 1.15).
7. Once the Match starts, no one is promoted and the waitlist can't be joined.
8. The waitlist is capped at 50 people (keeps the array small).
9. A Player let in gets the normal `approved` notification and their 1-hour reminder (1.24).
