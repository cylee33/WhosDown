## Goal

On an Open Match, a Player taps Join once and is in. Everyone sees the count change live.

## Data

| ID | Read / write | Path and fields |
|---|---|---|
| R2, R4 | read (listener) | As in 1.8 |
| W6 | write (transaction) | Re-read `matches/{matchId}`; if not Full: set `rsvps/{me}` to `status: "approved"`, `userId`, `displayName`, `skillLevel`, `isHost: false`, `requestedAt`, `respondedAt` (server time), `checkedIn: false`, `attended: null`; `joinedCount += 1`; update `attendeePreview` (first 6 initials) |

**Security rules this feature needs:** a Player can set their own RSVP to `approved` only when the Match's `joinType == "open"`, `joinedCount` goes up by exactly 1 and stays ≤ `playerLimit`, the Match is scheduled and not started, and the Player isn't the Host.

## Rules and edge cases

1. "Join" shows when the Match is Open, not Full, scheduled, not started, and the Player has no active RSVP (none, or `left`).
2. One tap, no confirmation sheet (the feature is "one-tap join").
3. While the transaction runs, the button shows a spinner and can't be tapped again.
4. **Race for the last spot:** the transaction re-reads; if Full, nothing is written, the Player sees "That spot was just taken", and the button becomes "Full · Join waitlist" (1.17).
5. **Rejoin after leaving** is allowed if a spot is open (H37's note).
6. After joining, the screen switches to H14 and the count updates for everyone live.
7. Joining schedules the 1-hour reminder (1.24) when that feature exists.
8. Guests get H34 (1.3). The Host never sees Join.
