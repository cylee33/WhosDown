## Goal

A teammate can clone the repo, open Xcode, start the emulator, seed it, and run an app that launches on the tab bar. The shared models, repositories, design system, and security rules that every feature builds on are in place.

**Security rules v1:** deny by default. Public read of `users`, `venues`, `matches`, and `rsvps` for any signed-in user, including Guests. `users/{uid}/private/settings` is read and written by its owner only. Anonymous users can't write anything. Each feature then adds its own write rules with tests.

## Rules and edge cases

1. Bundle ID `edu.cmu.whosdown`, minimum iOS 26, Swift settings are the Xcode 27 defaults for a new app (D16). Record them in architecture §4.
2. Packages: Firebase (`FirebaseAuth`, `FirebaseFirestore`, `FirebaseStorage`) through Swift Package Manager. No GeoFireUtils (D50).
3. Debug builds connect to the emulator (Auth 9099, Firestore 8080, Storage 9199) and Release builds connect to `whosdown-57e99`. One switch, in `App/`.
4. Views and view models get repositories through one dependency container created at app start (ADR-0001). Previews use the fakes.
5. Three top-level folders, `Models/`, `Views/`, `ViewModels/` (ADR-0009). `Views/` and `ViewModels/` each have one subfolder per area: `Onboarding`, `Discover`, `Match`, `Host`, `Profile`, `Notifications`. All are Xcode synchronized folders.
6. Design system: color tokens (green accent, status colors: pending yellow, approved green, declined red, waitlisted orange), spacing on the 8-point grid, SF Pro text styles with Dynamic Type, and base components: primary button, secondary button, chip, card, list row. Light mode only (D34, D35).
7. Seed (D41): emulator only, unless a flag and a key outside git are given. Pittsburgh Venues (for example CMU Soccer Field, Schenley Oval, Gesling Stadium), about 10 Matches across sports, join types, and statuses (one Full with a waitlist, one with Join requests, one in the past), and 5 test Players with known passwords listed in `firebase/seed/README.md`.
8. `GoogleService-Info.plist` for the new app is committed (D40). Registering the iOS app in the Firebase console is a step Chris does by hand; the CLI can do it after `firebase login`.
