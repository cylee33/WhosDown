## Hand-off note

- **Works now:** "Explore as guest" (anonymous sign-in); `Session.requireAccount(then:)` and `Session.showGate(_:)` open H34 (`GuestGateSheet`) over the current screen; Create account from the gate **links** the Guest (same uid, token refreshed so rules see the upgrade), then onboarding covers the tab bar and the Guest ends up where they were; Sign in from the gate switches accounts in place. The Matches and Create tabs show `GuestPromptView`; the Profile tab shows the empty "+" `GuestProfileView`. Tests: 4 Guest unit tests, 1 emulator integration test (link keeps the uid and the profile write passes rules), 1 rules test.
- **Left to do:** nothing for 1.3. **Every later feature with an action must wrap it:** `session.requireAccount { … }` (join, request, waitlist, chat, report, edit). That's how rule 2 is kept as those features land.
- **Gotchas:**
  - `Session` listens to ID-token changes (not just sign-in changes) because linking keeps the same user, and ignores repeats so hourly token refreshes don't reset state.
  - Signing in from the gate leaves the old anonymous user behind in Firebase Auth. That's harmless; no Firestore data is ever written for Guests.
  - A Guest has no Sign out button (rule 7 is covered by reinstalling). Add one only if testers ask.
  - Firebase keeps the sign-in in the iOS Keychain, which survives deleting the app. `Session.start()` therefore signs out once on the first launch after an install (flag `hasLaunchedBefore` in UserDefaults), so a reinstall really returns to H01.
- **Next step:** 1.4 Onboarding.

## Goal

Someone can explore WhosDown without an account. The moment they try to do something, a sheet asks them to create an account or sign in, then brings them back.

## Screens

| Screen | What this feature owns on it |
|---|---|
| H01 Welcome | "Explore as guest" |
| H34 Guest join gate | Bottom sheet over the current screen: "Sign in to join", "Guests can browse everything.", explainer, "Create account", "Sign in", "Keep browsing" |
| Matches tab | For a Guest: a short prompt with "Create account" and "Sign in" instead of the tab's content |
| Profile tab | For a Guest: an empty profile with a "+" placeholder avatar and "Sign in" / "Create account" buttons |

## Data

| ID | Read / write | Path and fields |
|---|---|---|
| Auth | — | `signInAnonymously()`; `currentUser.link(with: EmailAuthProvider.credential(...))` on upgrade |
| W1 | write | After linking, the same W1 as 1.2 creates the profile |

No Firestore document is written for a Guest; `isGuest` comes from Auth (`isAnonymous`).

**Security rules this feature needs:** anonymous users (`request.auth.token.firebase.sign_in_provider == "anonymous"`) can read public data and write nothing. Test this in 1.1's rules tests.

## Rules and edge cases

1. A Guest can see everything public: Discover map and list, filters, Match details, roster, weather, other Players' profiles (D27).
2. **The gate:** joining, requesting, joining a waitlist, hosting (Create tab), chat, reporting, and editing a profile open H34 and write nothing.
3. **Create account** on H34 opens H02 and **links** the anonymous user, so the uid stays the same. Then onboarding (1.4), then back to the screen where the gate opened.
4. **Sign in** on H34 opens H41 and signs in to the existing account. The anonymous session is discarded. Then back to the same screen.
5. **Keep browsing** closes the sheet.
6. Filter choices a Guest makes stay for the session only (nothing is saved).
7. Signing out of a Guest session (or a reinstall) just returns to H01.
